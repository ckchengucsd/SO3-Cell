# SO3-Cell: Standard Cell Layout Automation Framework for Simultaneous Optimization of Topology, Placement, and Routing
The **SO3 standard cell generation framework** is the first framework that simultaneously optimizes
schematic topology, transistor placement, and in-cell routing.

This repository provides not only the full source code for the SO3 framework, but also a complete
set of pre-generated library views and related enablement assets required for practical evaluation.

If you use SO3 in any published work, we would greatly appreciate it if you could cite this paper [\[1\]](https://vlsicad.ucsd.edu/Publications/Conferences/418/c418.pdf).

We also emphasize that none of the data included here should be interpreted as benchmarking, and
no value judgments are made regarding the relative merits of commercial EDA tools.

![SO3 Framework](./Framework.png)

The repository structure is as follows:

*   **`./Framework`:** This directory holds the core source code of the **SO3 Framework**, which is responsible for the automated generation of standard cell layouts. This directory consists of the following subdirectories:
    *   **CellGen:** This directory contains the code for generating GDS and LEF files of standard cells.
    *   **PostCellGen:** This directory contains the code for performing LVS/PEX and cell characterization (e.g., .lib file generation) based on the generated standard cell GDS files.
    *   **BlockDesign:** This directory includes scripts for evaluating the generated standard cells.
*   **`./Enablement`:** This directory provides a complete enablement kit, containing both the inputs for the framework and its pre-generated outputs.
    *   **Circuit Netlists (`./Enablement/cdl`):** The SPICE netlists that describe the circuits to be generated.
    *   **Timing Libraries (`./Enablement/lib`):** These are timing libraries used for static timing analysis. The files in this directory are pre-generated Liberty files, and these files can also be generated directly by using the **PostCellGen** directory.
    *   **Physical Libraries (`./Enablement/lef`):** These are LEF files that capture the physical abstracts of the cells for placement and routing. You can create LEF files using *Cadence Abstract* from GDS files.
    *   **Layout Data (`./Enablement/gds`):** These are the final GDSII stream files containing the full mask layout data. GDS files can be generated through the **CellGen** directory.
    *   **Database Files (`./Enablement/db`):** These are Synopsys-compatible database (.db) files for synthesis and P&R tools. They can be generated by converting Liberty files using *Synopsys Library Compiler*.

## SO3 L3 Addon — Full Adder Fix and Prefix Adder Cells

The original L3 Full Adder circuit has a known issue. **SO3_L3_addon** supplies
its corrected implementation, `FA_X1_NEW`, and the prefix-combine cell
`PREFIXADD_X1` for arithmetic and prefix-logic optimization. The original L3
library is preserved; the addon is a separate library with Liberty name
`SO3_L3_addon`.

| Delivered file | Purpose |
| --- | --- |
| `Enablement/lib/SO3_L3_addon.lib` | Liberty timing, power, logic and area models |
| `Enablement/db/SO3_L3_addon.db` | Synopsys compiled logical/timing library |
| `Enablement/lef/SO3_L3_addon.lef` | Physical abstracts, pins and obstructions |
| `Enablement/gds/SO3_L3_addon.gds` | GDSII cell layouts for physical integration/signoff |
| `Enablement/cdl/SO3_L3_addon.cdl` | Transistor netlists for circuit/LVS use |

Actual Liberty cells and functions:

- `FA_X1_NEW`: inputs `A B CI`, outputs `CO S`; `CO = A*B + A*CI + B*CI`,
  `S = A xor B xor CI`; power pins `VDD VSS`.
- `PREFIXADD_X1`: inputs `G0 G1 P0 P1`, outputs `G_OUT P_OUT`;
  `G_OUT = G1 + P1*G0`, `P_OUT = P1*P0`; power pins `VDD VSS`.
  This delivery contains one prefix cell.

The corrected FA is available as a replacement implementation after validation
in the consuming flow, but is **not a drop-in cell-name/pin replacement**:
baseline FA cells use different names and complemented outputs (`CON`, `SN`).
Remap logic and check output polarity, physical sites and timing constraints;
do not simply rename existing instances. Keep the corrected addon cell available
if validated while excluding the baseline Full Adders below.

The supplied `Enablement/SO3_L3_addon_delivery.tar.gz` is retained unchanged. Its
16 members include all five combined views, individual CDL/GDS/LEF views,
`README.txt`, and validation/provenance/checksum JSON files. Every archive member
was compared with the source directory. The combined views duplicate the loose
files deliberately for direct consumption and delivery traceability; an expanded
`SO3_L3_addon/` tree is not stored again. Source build scripts, logs, extraction
scratch data and site-specific symlinks outside the supplied delivery archive
are not copied. `Enablement/SO3_L3_addon.sha256` records the six copied files.

See [the Fusion Compiler addon setup example](Framework/BlockDesign/SO3_L3/ADDON.md)
for using the addon alongside L3. Source validation reports are supplied evidence,
not validation rerun by this repository update. No Fusion Compiler, characterization,
LVS, DRC or signoff run was performed for this update. The source README notes
characterization warnings (including negative delays at some slew/load points)
and no separate DRC signoff run; review these before use.

## Fusion Compiler — Full Adder dont_use Requirement

**Mandatory: exclude the original baseline Full Adder implementations in L1,
L2 and L3 from Fusion Compiler synthesis and implementation. This requirement
does not exclude the corrected `SO3_L3_addon/FA_X1_NEW`.**

The checked-in Liberty files identify these exact targets:

| Baseline Liberty library | Full Adder cell |
| --- | --- |
| `SO3_L1_tt_0.7_25` | None present in this checkout (41 cell definitions; CDL also has no FA) |
| `SO3_L2_tt_0.7_25` | `FA_X1_SH` |
| `SO3_L3_tt_0.7_25` | `FA_X1_DH` |

There is no valid L1 FA command to supply for this delivery. If using another
L1 revision containing a Full Adder, inspect that Liberty and add its exact
library/cell target before running the flow. Do not disable generic arithmetic
cells or use a cross-library FA wildcard.

Ready-to-copy Tcl for the original L2/L3 libraries that are actually loaded:

```tcl
# Apply after reference/logical libraries are loaded, before compile_fusion.
# L1 in this checkout contains no Full Adder.
foreach target {
    SO3_L2_tt_0.7_25/FA_X1_SH
    SO3_L3_tt_0.7_25/FA_X1_DH
} {
    set fa_cells [get_lib_cells -quiet $target]
    if {[sizeof_collection $fa_cells] > 0} {
        set_dont_use $fa_cells true
        # The repository RM uses purpose exclusions for FC optimization:
        set_lib_cell_purpose -exclude {optimization hold cts power} $fa_cells
    } else {
        puts "Baseline FA not loaded under expected name: $target"
    }
}
```

The library names above are confirmed from Liberty, not from a running FC
session. Check the loaded library names and cell collections in your FC release;
if a baseline library is loaded but its target does not resolve, stop and correct
the exact library qualification. The `set_dont_use` example has not been executed
in FC; confirm command support with `help set_dont_use` in your installed release.
The existing RM's confirmed convention is `set_lib_cell_purpose -exclude`.

Apply the restrictions through your flow's library-cell restriction hook after
libraries load and before any synthesis/mapping or implementation optimization.
In the supplied RM this is `TCL_LIB_CELL_DONT_USE_FILE` (configured in
`initial/rm_setup/sidefile_setup.tcl`), sourced by `set_lib_cell_purpose.tcl`.
Preserve other restrictions in that hook. Reapply/check restrictions on resumed
implementation sessions and after library reloads, and verify no baseline FA
instances remain in mapped designs. These commands prevent future selection;
they do not repair pre-existing instances. Existing production scripts are
unchanged by this update.

## Prerequisites

To set up and run this project, you will need the following dependencies installed on your system.

### System Dependencies

*   **Python** (version 3.10)
*   **KLayout** (version 0.29)
*   **Gurobi** (version 12.0.1) with valid license

### Gurobi License

This project utilizes **Gurobi** as its MILP (Mixed-Integer Linear Programming) solver. Therefore, a valid Gurobi license is required to run the framework.

If you are a student or a member of a university faculty, Gurobi provides a **free, full-featured academic license**. Please visit the link below to register and obtain your license:

Install the required Python packages using pip:

```bash
pip install gurobipy
```

## Running the Framework

### Standard Cell Generation
Follow these steps to generate the standard cell layouts.

First, change your current directory to the `Framework/CellGen` directory, which contains the main execution script.

```bash
cd Framework/CellGen
```

Next, run the `run_cell.sh` script. This will initiate the cell generation flow, from reading the netlist to generating the final GDSII layout file.

```bash
./run_cell.sh --help

# Generate all cells from a CDL name under Enablement/cdl
./run_cell.sh --cdl-name SO3_L1

# Single-height (default) specific cells
./run_cell.sh --cdl-name SO3_L1 --cells "NAND2_X1 INV_X1"

# Double-height, N-first (NMOS row at bottom, PMOS row on top)
ARCH=DH MH_ORDER=N_FIRST ./run_cell.sh --cdl-name SO3_L1 --cells "NAND2_X1"

# Double-height, P-first (PMOS row at bottom, NMOS row on top)
ARCH=DH MH_ORDER=P_FIRST ./run_cell.sh --cdl-name SO3_L1 --cells "NAND2_X1"
```

`run_cell.sh` wraps `bin/run_cell.py`, which selects the appropriate ILP solver script (`src/ILP_SO3_SH_flex.py` for single-height, `src/ILP_SO3_DH_flex.py` for double-height) based on the `--arch` option.

### Standard Cell Verification and Characterization
In this part, LVS/PEX and cell characterization are performed for the generated standard cells.
All scripts used in this stage are derived from PROBE3.0 [\[2\]](https://vlsicad.ucsd.edu/Publications/Journals/j143.pdf).

First, change your current directory to the `Framework/PostCellGen` directory:

```bash
cd Framework/PostCellGen
```

Then, run the following command:

```bash
./run_all.sh
```

`run_all.sh` automatically calls `run.sh` with the appropriate library name.
`run.sh` performs LVS/PEX and cell characterization using the specified CDL and GDS files.
If you wish to use different CDL or GDS files, please modify the *CDL_FILE* and *GDS_FILE* paths inside the script accordingly.

Please note that running this step requires licenses for *Cadence Pegasus, Cadence Quantus, and Cadence Liberate*.

### Block Design Evaluation
To perform block-level evaluation, follow the steps below.

Please change your directory to the `Framework/BlockDesign/{LIB_NAME}` directory. (LIB_NAME can be one of SO3_L1, SO3_L2, SO3_L3, etc.)

```bash
cd Framework/BlockDesign/{LIB_NAME}
```

Then, run the following command:

```bash
./run_multi_area.sh
```

Please note that running this step requires license for *Synopsys Fusion Compiler*.
